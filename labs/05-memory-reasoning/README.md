# Lab 05：记忆、推理与模型服务专项

> 状态：planned

## Lab 定位

本 Lab 关注 Agent 如何保存、检索、压缩和评估记忆，也关注模型服务层如何影响 Agent 的延迟、成本、稳定性和吞吐。

## 对应章节

- 第 03 章：第一次 LLM 调用
- 第 13 章：Memory 与 State
- 第 15 章：Agent Evaluation 评估方法
- 第 16-18 章：观测、成本和生产化

## 推荐项目

- 主案例：[mem0](https://github.com/mem0ai/mem0)
- 主案例：[Letta](https://github.com/letta-ai/letta)
- 主案例：[LiteLLM](https://github.com/BerriAI/litellm)
- 进阶案例：[SGLang](https://github.com/sgl-project/sglang)
- 候选观察：[EverOS](https://github.com/EverMind-AI/EverOS)

## 承接主线

读者已经知道一次模型调用不是完整系统。本 Lab 进一步拆解两类基础设施：长期记忆如何进入 Agent 系统，以及模型网关、推理引擎如何影响复杂 Agent 的成本、延迟和稳定性。

## 学习任务

- 任务 1：拆出记忆系统的写入、检索、更新、删除和评估流程。
- 任务 2：设计一组记忆质量测试，例如是否记住用户偏好、是否错误记住临时信息。
- 任务 3：观察模型网关或推理引擎如何通过统一接口、日志、缓存、批处理或并发影响 Agent 性能。

## 项目迁移

把能力迁移到“AI 学习助手”：先实现学习偏好和章节进度记忆，再设计可回滚、可删除的记忆管理。

## 产出标准

- 一张记忆生命周期图。
- 一组记忆评估样例。
- 一份成本、延迟和失败处理观察表。

## 写作边界

不要把所有历史对话都叫记忆，也不要把模型网关当成第一次调用的必要复杂度。要区分上下文、状态、长期记忆、模型服务、缓存和日志。
