# 第 1 章：AI 项目到底在做什么

> 状态：drafting

做 AI 项目前，先别急着选框架，也别急着说“我要做 Agent”。

先判断一件事：

```text
这个需求到底需要哪种 AI 能力？
```

本章只教一个能力：**把一个模糊需求判断成合适的 AI 项目类型**。

你会用一个简单流程判断：

```text
能不能用普通程序解决？
-> 是否需要模型理解自然语言？
-> 是否需要外部资料？
-> 是否需要调用工具？
-> 是否需要动态决定下一步？
```

最后你会为自己的项目写出第一版项目地图。

## 先看一个需求

我们要做一个贯穿项目：

```text
AI 学习助手
```

一个容易失控的描述是：

```text
做一个全自动学习 Agent，能规划路线、查资料、出题、批改、记忆、复习提醒。
```

这不是第一版需求，而是很多版本叠在一起。

第一版可以压成一句话：

```text
用户输入一个学习问题，系统返回解释、常见误区和一个练习任务。
```

这时它还不是 Agent。它更像一个 **结构化 LLM 应用**。

为什么？因为第一版只需要模型生成一次结构化回答，不需要自己规划多步任务，也不需要调用外部工具。

这就是项目判断的价值：**先判断形态，再决定技术路线**。

## AI 项目的 6 种常见形态

先记住这张表。后面的章节都会沿着这张表往下走。

| 项目形态 | 什么时候用 | 例子 |
| --- | --- | --- |
| 普通程序 | 规则明确、结果确定 | 手机号校验、金额计算、权限判断 |
| 单次 LLM 调用 | 输入短、只需要一次生成 | 总结一段话、改写一句文案 |
| 结构化 LLM 应用 | 需要模型按固定字段输出 | 工单分类、信息抽取、学习建议 |
| RAG 应用 | 回答必须依赖外部资料 | 课程知识库问答、公司制度问答 |
| AI 工作流 / Tool Calling | 步骤较固定，但需要查系统或调用工具 | 查询订单后生成客服回复 |
| Agent | 步骤不固定，需要根据中间结果决定下一步 | 研究一个主题、分析一个代码仓库 |

不要把所有 AI 项目都叫 Agent。

Agent 的关键不是“用了大模型”，也不是“会调用工具”，而是：

```text
系统会根据目标、上下文和中间结果，动态决定下一步做什么。
```

如果流程能提前写死，优先做工作流，不要急着做 Agent。

## 判断流程

下面这个流程可以直接用来判断需求。

### 第一步：普通程序能不能解决？

如果规则清楚，优先用普通程序。

例子：

```text
判断手机号格式是否正确。
```

这不需要 AI。正则或普通校验逻辑更稳定。

### 第二步：是否需要模型理解自然语言？

如果输入是自然语言，或者输出需要总结、改写、分类、生成，就可以考虑 LLM。

例子：

```text
把一段会议记录总结成 5 个要点。
```

这适合单次 LLM 调用。

### 第三步：是否需要稳定结构？

如果输出要进入后续程序，就不要只让模型自由发挥，要让它输出固定字段。

例子：

```text
把客服工单分成：问题类型、紧急程度、建议处理人。
```

这适合结构化 LLM 应用。

### 第四步：是否需要外部资料？

如果答案必须依赖文档、课程资料、公司制度、代码仓库，就需要 RAG。

例子：

```text
根据课程笔记回答“什么是 RAG”。
```

这不应该只让模型凭记忆回答。更合适的是检索笔记，再让模型基于检索结果回答。

### 第五步：是否需要调用工具？

如果模型需要查订单、读文件、跑测试、访问网页，就进入 Tool Calling 或工作流。

例子：

```text
用户问订单什么时候发货，系统先查订单状态，再生成客服回复。
```

这里模型不能凭空回答，必须调用订单查询工具。

### 第六步：是否需要动态决定下一步？

如果任务不能提前写死步骤，需要根据中间结果继续决定下一步，才考虑 Agent。

例子：

```text
围绕一个主题做调研：先搜索资料，再筛选来源，再整理提纲，再写初稿，再检查事实问题。
```

这个任务每一步都会影响下一步，更接近 Agent。

## 项目锚点：AI 学习助手第一版

现在判断我们的项目。

第一版需求：

```text
用户输入一个学习问题，系统返回解释、常见误区和一个练习任务。
```

按上面的流程判断：

| 判断问题 | 结论 |
| --- | --- |
| 普通程序能解决吗？ | 不能，解释和练习生成很难写死规则 |
| 是否需要理解自然语言？ | 需要 |
| 是否需要稳定结构？ | 需要，最好固定输出“解释 / 误区 / 练习” |
| 是否需要外部资料？ | 第一版不需要 |
| 是否需要工具？ | 第一版不需要 |
| 是否需要动态决定下一步？ | 第一版不需要 |

所以第一版是：

```text
结构化 LLM 应用
```

不是 Agent。

后面它可以升级成：

- 接入课程资料：RAG。
- 保存学习记录：状态和记忆。
- 生成练习并检查答案：工具调用。
- 根据学习目标持续推进：Agent。

但第一版不要同时做这些。

## 成熟项目讲解：OpenClaw 和 mem0

本章只观察项目定位，不读源码。

对应源码 Lab：

- [Lab 01：通用核心框架](../../labs/01-core-frameworks/README.md)
- [Lab 05：记忆、推理与模型服务专项](../../labs/05-memory-reasoning/README.md)

OpenClaw 更像一个面向用户的 AI 助手产品。看它时，重点观察：

- 它给用户提供什么入口？
- 它帮用户完成什么任务？
- 它为什么不是简单的模型调用？

mem0 更像一个给开发者使用的记忆基础设施。看它时，重点观察：

- 它给其他 AI 应用提供什么能力？
- 它为什么不是一个完整聊天产品？
- 如果 AI 学习助手未来要记住学习进度，可以借鉴它哪一类能力？

这两个项目帮助你区分两类 AI 项目：

| 类型 | 代表 | 特点 |
| --- | --- | --- |
| 应用层产品 | OpenClaw | 直接面向用户，帮用户完成任务 |
| 基础设施组件 | mem0 | 给其他 AI 应用提供能力 |

我们的“AI 学习助手”第一阶段先做应用层产品。
