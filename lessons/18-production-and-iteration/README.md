# 第 18 章：Production 上线、成本与迭代

> 状态：planned

## 本章定位

把前面学到的 AI 和 Agent 能力放到真实运行环境中，讨论上线、成本、性能、监控和持续迭代。

## 承接上一章

上一章讲了安全和可信。本章继续处理生产环境中的成本、稳定性、部署和运营问题。

## 铺垫下一阶段

本章结束后，读者应该能进入综合项目，把全书能力串成一个可演示、可评估、可迭代的 Agent 项目。

## 学习目标

- 能说清 Demo 和生产系统之间的差距。
- 能设计成本、限流、缓存、降级和监控策略。
- 能用评估数据和线上反馈持续迭代 AI / Agent 系统。

## 本章产出

- 一份上线检查清单。
- 一张生产链路图。
- 一个最小服务化改造方案。

## 学习任务

- 为项目写一份上线检查清单，覆盖配置、成本、限流、日志、告警和回滚。
- 估算一次完整任务的模型调用成本和最坏情况下的重试成本。
- 设计一个迭代机制，说明如何根据评估集和用户反馈更新 Prompt、RAG、工具和安全规则。

## 项目锚点

“AI 学习助手”在本章形成可演示的项目闭环：可运行、可评估、可追踪、可限制权限、可持续迭代。其他可选项目也应该在本章形成最小上线方案，而不是停留在 notebook 或脚本 Demo。

## 成熟项目讲解

- 主案例：OpenClaw、mem0、LiteLLM、LangGraph。
- 对比案例：Dify、SGLang。
- 讲解切口：产品入口、记忆服务、模型网关、状态化执行、部署、成本和迭代。
- 对应源码 Lab：[Lab 01：通用核心框架](../../labs/01-core-frameworks/README.md)、[Lab 05：记忆、推理与模型服务专项](../../labs/05-memory-reasoning/README.md)、[Lab 07：低代码与无代码 Agent 平台](../../labs/07-low-code/README.md)。
- 迁移到项目：把“AI 学习助手”收束成可演示、可评估、可追踪、可安全迭代的最小上线方案。

## 开源案例观察

对比 OpenClaw、mem0、LiteLLM 和 LangGraph 的生产化侧重点：产品入口、记忆服务、模型网关、状态化执行。读者要理解一个 Agent 项目上线时通常需要多个基础设施组件配合。

## 本章要写什么

- Demo 和生产系统的区别。
- 部署方式和配置管理。
- 成本估算、限流和缓存。
- 延迟、并发和重试。
- 监控、告警、灰度和回滚。
- 如何持续迭代 Prompt、RAG、工具和评估集。

## 本章不要写什么

- 不要把生产化写成单一云平台部署教程。
- 不要忽略成本和失败恢复。
- 不要把上线当成课程终点，应该强调持续迭代。

## 小白易卡点

- 以为 Demo 能跑就等于可以上线。
- 没有估算模型成本和失败重试成本。
- 缺少灰度、回滚和持续评估机制。

把前面的小 Agent 包装成一个最小服务，增加配置、日志、错误处理和成本统计。
