# 第 8 章：RAG 进阶与评估

> 状态：planned

## 本章定位

帮助读者理解 RAG 跑通之后为什么还会答不好，以及如何定位问题。

## 承接上一章

上一章跑通了最小 RAG。本章继续解决检索不准、上下文不合适、回答不可靠等问题。

## 铺垫下一章

下一章会讲工具调用。本章让读者先学会评估外部信息是否被模型正确使用，为后续评估 Agent 行动打基础。

## 学习目标

- 能区分“检索错了”和“模型回答错了”。
- 能用小型测试集评估 RAG 效果。
- 能根据失败类型调整切分、召回、重排和 Prompt。

## 本章产出

- 一组 RAG 测试问题。
- 一张 RAG 失败原因分类表。
- 一份检索结果和最终回答的调试记录。

## 学习任务

- 为第 7 章知识库准备至少 10 个测试问题。
- 记录每个问题的检索结果、回答结果和失败原因。
- 调整一次切分、召回数量或 Prompt，并比较调整前后的效果。

## 项目锚点

“AI 学习助手”在本章要有第一版知识问答评估集。研究写作 Agent 要评估资料是否被正确引用，客服工单 Agent 要评估答案是否命中正确 FAQ。

## 成熟项目讲解

- 主案例：mem0。
- 对比案例：Dify。
- 讲解切口：把记忆质量、检索质量和回答质量分开评估。
- 对应源码 Lab：[Lab 05：记忆、推理与模型服务专项](../../labs/05-memory-reasoning/README.md)、[Lab 07：低代码与无代码 Agent 平台](../../labs/07-low-code/README.md)。
- 迁移到项目：为“AI 学习助手”建立小型评估集，记录检索片段、引用依据和回答结果。

## 开源案例观察

观察 mem0 的记忆评估思路，并把它迁移到 RAG：不要只看最终回答，还要看检索片段、引用依据和长期表现。

## 本章要写什么

- RAG 常见失败原因。
- Chunk 大小、召回数量和重排的影响。
- 检索评估和回答评估的区别。
- 如何构建小型测试集。
- 如何记录检索片段和最终回答。

## 本章不要写什么

- 不要展开 Agent 评估。
- 不要把所有检索算法都讲一遍。
- 不要只讨论工具选型。

## 小白易卡点

- 只看最终回答，不看检索片段。
- 检索不到时直接怪模型。
- 不了解测试集为什么要固定，导致每次调试无法比较。

## 建议示例

准备 10 个问题，检查每个问题是否检索到了正确资料，以及回答是否引用了正确依据。

画一张 RAG 调试流程图：问题、检索结果、上下文、回答、评估。
