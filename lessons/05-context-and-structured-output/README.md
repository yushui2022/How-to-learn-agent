# 第 5 章：上下文工程与结构化输出

> 状态：planned

## 本章定位

帮助读者理解上下文不是越多越好，模型输出也要尽量变成程序能处理的结构化结果。

## 承接上一章

上一章解决了如何写清楚 Prompt。本章进一步解决：Prompt 之外还要放什么上下文，以及如何让输出可解析。

## 铺垫下一章

下一章会讲 AI 工作流。本章需要让读者能把模型输出交给后续程序步骤处理。

## 本章要写什么

- 什么是上下文工程。
- 如何选择放入上下文的信息。
- 如何避免上下文过长、过乱。
- 结构化输出的价值。
- JSON、Schema、字段校验和失败重试的基本思路。

## 本章不要写什么

- 不要深入向量检索。
- 不要提前讲完整评估系统。
- 不要把结构化输出写成某个 SDK 的参数说明。

## 建议示例

让模型把一段用户需求整理成固定字段，例如目标、输入、输出、限制和风险。

## 建议图解

画一张从非结构化文本到结构化结果的转换流程。
