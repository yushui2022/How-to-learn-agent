# 第 9 章：Tool Calling 工具调用

> 状态：planned

## 本章定位

教读者让模型从生成文本走向调用外部能力，例如查询数据、调用 API 或执行受限操作。

## 承接上一章

前两章讲了让模型使用外部知识。本章扩展到让模型使用外部工具。

## 铺垫下一章

下一章会正式定义 Agent。本章需要先让读者理解“行动”是如何通过工具调用发生的。

## 学习目标

- 能解释 Tool Calling 和普通文本生成的区别。
- 能设计一个清晰、可校验的工具 Schema。
- 能处理工具调用失败、参数错误和权限边界。

## 本章产出

- 两个最小工具定义。
- 一份工具参数校验逻辑。
- 一份工具调用日志样例。

## 学习任务

- 为项目设计 2 个工具，并写清楚工具输入、输出、权限和失败情况。
- 实现或伪代码描述工具参数校验。
- 记录一次完整工具调用日志，包括模型请求、工具执行和最终回答。

## 项目锚点

“AI 学习助手”可以增加查询知识库、生成练习题、保存学习记录等工具。客服工单 Agent 可以增加查询订单或工单状态工具，代码仓库助手可以增加文件搜索或测试运行工具。

## 成熟项目讲解

- 主案例：OpenClaw。
- 对比案例：browser-use、SmolAgents。
- 讲解切口：技能系统、工具 Schema、参数校验、调用日志和权限边界。
- 对应源码 Lab：[Lab 06：浏览器与工具自动化](../../labs/06-browser-tools/README.md)、[Lab 08：轻量入门与研究级 Agent](../../labs/08-lightweight-research/README.md)。
- 迁移到项目：为“AI 学习助手”定义查询资料、生成练习、保存学习记录三个受控工具。

## 开源案例观察

观察 OpenClaw 的技能系统和 LangGraph 的工具节点。重点学习工具 Schema、参数校验、调用日志和权限边界，而不是只看模型如何选择工具。

## 本章要写什么

- Tool Calling 的基本概念。
- 工具 Schema 如何设计。
- 参数校验和错误处理。
- 工具调用的权限边界。
- 如何记录工具调用日志。

## 本章不要写什么

- 不要直接进入复杂 Agent 框架。
- 不要让工具执行高风险操作。
- 不要忽略失败和重试。

## 小白易卡点

- 以为模型真的“执行”了工具，而不是应用程序执行工具。
- 工具参数设计太随意，导致模型难以正确调用。
- 忽略工具副作用和权限限制。

## 建议示例

给模型两个工具：查询本地资料和执行简单计算，让模型根据用户问题选择是否调用工具。

## 建议图解

画一张工具调用时序图：模型请求工具、应用执行工具、结果返回模型、模型生成最终回答。
