# 第 12 章：Planning 任务拆解与计划执行

> 状态：planned

## 本章定位

教读者处理更长任务：先拆解任务，再按计划执行，并在必要时调整计划。

## 承接上一章

上一章讲了 Agent 的单步循环。本章把单步循环扩展成多步骤任务执行。

## 铺垫下一章

下一章会讲 Memory 与 State。本章会产生任务计划、执行进度和中间结果，这些都需要状态管理。

## 学习目标

- 能把复杂目标拆成可执行子任务。
- 能区分 Planner、Executor 和 Reviewer 的职责。
- 能判断什么时候需要重新规划，什么时候应该停止。

## 本章产出

- 一个任务拆解样例。
- 一张 Planner / Executor 流程图。
- 一份计划执行记录。

## 学习任务

- 选择一个项目中的长任务，把它拆成 4 到 6 个可执行步骤。
- 区分哪些步骤由 Planner 负责，哪些步骤由 Executor 负责。
- 设计一个重新规划条件，例如检索失败、工具失败或用户修改目标。

## 项目锚点

“AI 学习助手”在本章可以把“帮我学会 RAG”拆成资料检索、概念解释、练习生成、答案检查和复习建议。研究写作 Agent 可以把“写一篇调研文章”拆成搜索、筛选、提纲、初稿和审阅。

## 成熟项目讲解

- 主案例：LangGraph。
- 对比案例：AutoGen、CrewAI。
- 讲解切口：Planner、Executor、Reviewer 的职责边界，以及什么时候需要重新规划。
- 对应源码 Lab：[Lab 01：通用核心框架](../../labs/01-core-frameworks/README.md)、[Lab 04：多智能体协作](../../labs/04-multi-agent/README.md)。
- 迁移到项目：把“学会 RAG”拆成可执行、可检查、可恢复的学习任务链。

## 开源案例观察

观察 LangGraph、AutoGen 和 CrewAI 对任务拆解、角色分工和执行流程的不同处理方式。重点看 Planner、Executor、Reviewer 的边界。

## 本章要写什么

- Planning 的价值和风险。
- 任务拆解方法。
- Planner 和 Executor 的关系。
- 计划执行、检查和重新规划。
- 如何避免计划过度复杂。

## 本章不要写什么

- 不要把 Planning 写成项目管理课。
- 不要提前展开长期记忆。
- 不要默认每个任务都需要复杂计划。

## 小白易卡点

- 以为计划一生成就应该完全照做。
- 把计划拆得太细，导致成本和延迟失控。
- 不知道如何处理执行过程中出现的新信息。

## 建议示例

让 Agent 把“调研一个主题并产出摘要”拆成搜索、阅读、整理和输出几个步骤。
