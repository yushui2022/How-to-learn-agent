# 第 16 章：Observability 观测与调试

> 状态：planned

## 本章定位

教读者记录和分析一次 AI 或 Agent 执行过程，知道问题发生在模型、Prompt、检索、工具还是状态管理。

## 承接上一章

上一章讲了如何评估好坏。本章继续讲发现问题后如何定位原因。

## 铺垫下一章

下一章会讲安全和可信。只有看得见执行过程，才能审计越权调用、异常输入和不可靠行为。

## 本章要写什么

- AI 应用需要记录哪些日志。
- Trace 的基本概念。
- Prompt、模型输出、检索结果、工具调用和错误信息如何关联。
- 如何复现一次失败。
- 如何用日志支持评估和迭代。

## 本章不要写什么

- 不要把内容写成某个观测平台广告。
- 不要记录敏感信息而不说明风险。
- 不要只讲后端日志，忽略 Agent 执行轨迹。

## 建议示例

给前面的 Agent 增加一次执行的 trace 记录，展示每一步输入、输出和工具结果。
