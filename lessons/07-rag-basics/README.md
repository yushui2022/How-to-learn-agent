# 第 7 章：RAG 基础

> 状态：planned

## 本章定位

教读者理解 RAG 的基本流程：不是让模型记住知识，而是在回答前把相关资料找出来。

## 承接上一章

上一章讲了工作流。本章把“检索资料”作为工作流中的关键步骤加入进来。

## 铺垫下一章

下一章会讲 RAG 的优化和评估。本章需要先让读者跑通最小 RAG 流程。

## 学习目标

- 能解释 RAG 解决什么问题，以及它和直接问模型的区别。
- 能理解文档加载、切分、索引、检索、生成的基本流程。
- 能跑通一个最小本地知识库问答流程。

## 本章产出

- 一个最小 RAG 示例。
- 一张 RAG 流程图。
- 一份文档切分和引用来源说明。

## 学习任务

- 为项目准备 3 到 5 份小文档，作为第一版知识库。
- 完成文档切分、索引和检索流程，并记录每个问题检索到了哪些片段。
- 让模型只基于检索片段回答，并在回答中保留来源信息。

## 项目锚点

“AI 学习助手”在本章加入课程资料或笔记知识库。研究写作 Agent 可以加入资料库，客服工单 Agent 可以加入客服 FAQ，代码仓库助手可以加入 README 和文档检索。

## 成熟项目讲解

- 主案例：Dify。
- 对比案例：OpenClaw、代码仓库助手类项目。
- 讲解切口：成熟产品如何把外部资料接入检索、引用和回答流程。
- 对应源码 Lab：[Lab 07：低代码与无代码 Agent 平台](../../labs/07-low-code/README.md)。
- 迁移到项目：为“AI 学习助手”接入课程资料或个人笔记，而不是让模型凭空回答。

## 开源案例观察

观察 OpenClaw 和代码仓库助手类项目如何把外部知识接入回答流程。重点区分“模型知道”和“系统检索到资料后让模型使用”。

## 本章要写什么

- RAG 解决什么问题。
- 文档加载、清洗和切分。
- Embedding 和向量检索的直观解释。
- 检索结果如何放进 Prompt。
- 引用来源的重要性。

## 本章不要写什么

- 不要深入复杂重排和评测指标。
- 不要引入太多向量数据库选型。
- 不要把 RAG 和 Agent 混在一起讲。

## 小白易卡点

- 以为 RAG 是让模型永久记住文档。
- 不知道为什么要切分文档。
- 检索到资料后，不知道怎样让模型只依据资料回答。

## 建议示例

读取几篇 Markdown 文档，检索相关片段，再让模型基于片段回答问题。

## 建议图解

画一张 RAG 流程图：文档、切分、索引、检索、生成、引用。
