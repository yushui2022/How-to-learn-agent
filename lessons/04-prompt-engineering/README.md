# 第 4 章：Prompt Engineering 入门

> 状态：planned

## 本章定位

教读者把随意提问变成可控任务描述，让模型更稳定地完成指定工作。

## 承接上一章

上一章读者已经跑通模型调用，并看到了输出不稳定的问题。本章开始解决“如何把任务讲清楚”。

## 铺垫下一章

下一章会讲上下文工程和结构化输出。本章需要先建立 Prompt 的基本组成：角色、任务、约束、示例和输出要求。

## 本章要写什么

- Prompt 的基本组成。
- 角色、任务、背景、约束和输出格式。
- Few-shot 示例什么时候有用。
- 如何从一次性 Prompt 迭代到可维护 Prompt。
- Prompt 常见错误。

## 本章不要写什么

- 不要把 Prompt 写成玄学技巧合集。
- 不要深入 JSON Schema 或解析。
- 不要展开 RAG 和 Agent。

## 建议示例

把第 3 章的随意提示词改造成结构清晰的任务提示词，并比较输出差异。

## 建议图解
