# 第 4 章：Prompt Engineering 入门

> 状态：drafting

第 3 章我们已经能把一个问题发送给模型，并拿到回答。

但“能调用模型”和“能让模型稳定完成任务”是两回事。

这一章解决一个更实际的问题：

```text
怎样把随口一问，改成可测试、可迭代、可复用的任务说明？
```

本章回答三个问题：

- 一个可维护 Prompt 应该包含哪些部分？
- 怎样用固定样例判断 Prompt 有没有变好？
- 成熟个人助手如何把用户意图转成任务、约束和输出要求？

学完本章，你要留下三份项目资产：

- 一个 Prompt 迭代记录：[prompt-iteration-template.md](./prompt-iteration-template.md)
- 一组 Prompt 测试样例：[prompt-test-cases-template.md](./prompt-test-cases-template.md)
- 一个对比示例：[prompt_iteration.py](../../examples/prompt-iteration/prompt_iteration.py)

## 先比较两个 Prompt

同样是问：

```text
什么是 RAG？
```

一个随意 Prompt 可能这样写：

```text
你是学习助手，回答用户问题。
```

它可能能回答，但输出容易出现几个问题：

- 解释长短不稳定。
- 有时只解释概念，不给练习。
- 有时术语太多，初学者看不懂。
- 遇到过大的问题时，可能直接硬答。

把它改成结构化 Prompt：

```text
角色：你是面向 AI Agent 初学者的中文学习助手。

任务：当用户提出学习问题时，输出三个部分：
1. 解释：用初学者能懂的话解释概念。
2. 常见误区：指出一个最容易误解的地方。
3. 下一步练习：给一个 10 分钟内能完成的小练习。

约束：
- 不要假装读取外部资料。
- 如果用户问题太大，先提出澄清问题。
- 回答控制在 300 字以内。
```

这个 Prompt 不一定完美，但它有一个明显优点：**你知道下一次该改哪里**。

Prompt Engineering 不是背“万能提示词”，而是把任务写成可以测试和迭代的说明书。

## Prompt 的 6 个组成部分

本章先掌握 6 个部分。

| 部分 | 作用 | AI 学习助手示例 |
| --- | --- | --- |
| 角色 | 告诉模型以什么身份回答 | 面向 AI Agent 初学者的中文学习助手 |
| 任务 | 告诉模型要完成什么 | 解释学习问题，并给出误区和练习 |
| 用户 | 告诉模型服务谁 | 中文初学者，不默认懂英文术语 |
| 约束 | 告诉模型不能做什么或必须遵守什么 | 不假装读取资料；回答不超过 300 字 |
| 输出要求 | 告诉模型答案长什么样 | 解释、常见误区、下一步练习 |
| 示例 | 给模型一两个参考输入输出 | 后面用测试样例补充 |

不是每个 Prompt 都要写得很长。

判断标准不是长度，而是：

```text
它是否让模型更稳定地完成你的项目任务？
```

## 从失败开始迭代

很多人写 Prompt 的方式是：

```text
写一个很长的 Prompt -> 感觉不错 -> 直接用
```

更可靠的方式是：

```text
准备测试样例 -> 写 v1 Prompt -> 跑样例 -> 记录失败 -> 改成 v2 Prompt
```

Prompt 迭代不要凭感觉，要看固定样例。

第 2 章我们已经准备了 5 个输入输出样例：

| 编号 | 输入 | 要观察的问题 |
| --- | --- | --- |
| 1 | 什么是 RAG？ | 是否解释清楚，是否指出不是让模型背知识 |
| 2 | Agent 和工作流有什么区别？ | 是否说清“动态决策”这个关键点 |
| 3 | ReAct 是什么？ | 是否给出观察、思考、行动的小练习 |
| 4 | 我总是把 Prompt 写很长怎么办？ | 是否能指出结构混乱，而不是泛泛鼓励 |
| 5 | 帮我学会所有 AI | 是否先澄清，而不是生成大而空的计划 |

这 5 个样例就是本章的 Prompt 测试集。

## 写出 v1 Prompt

AI 学习助手的 v1 Prompt 可以这样写：

```text
你是一个面向 AI Agent 初学者的中文学习助手。

你的任务是回答用户的学习问题。每次回答必须包含三部分：

1. 解释：用初学者能听懂的话解释概念。
2. 常见误区：指出一个最容易误解的地方。
3. 下一步练习：给一个 10 分钟内能完成的小练习。

约束：
- 回答控制在 300 字以内。
- 不要假装读取了课程资料、网页或外部文档。
- 如果用户问题太大或太模糊，先提出 1 到 3 个澄清问题。
```

这不是最终版本，但已经比“你是学习助手，回答问题”更可测试。

## 用样例判断 v1

跑完 5 个样例后，不要只写“效果不错”。

要记录具体失败。

| 失败表现 | 可能原因 | 怎么改 |
| --- | --- | --- |
| 没有给练习 | 输出要求不够硬 | 强调“必须包含三部分” |
| 解释里术语太多 | 用户画像不清楚 | 加上“不默认读者懂英文缩写” |
| 面对大问题直接规划 | 边界条件不清楚 | 加上“过大问题先澄清” |
| 练习太大 | 练习约束不清楚 | 加上“10 分钟内能完成” |

Prompt 的改动要能对应具体失败，而不是越写越长。

## 迭代到 v2

假设 v1 在“帮我学会所有 AI”这个样例上失败了，直接给了一个很大的学习计划。

v2 可以只改一个地方：

```text
如果用户提出的是过大的学习目标，例如“学会所有 AI”“从零成为专家”，
不要直接生成完整计划。先询问：
1. 用户当前基础是什么？
2. 用户希望学习哪个方向？
3. 用户可投入的时间是多少？
```

这就是一次合格的迭代：

```text
失败样例 -> 原因判断 -> 局部修改 -> 再跑样例
```

## Few-shot 示例什么时候有用

Few-shot 就是在 Prompt 里放一两个输入输出示例。

它适合三类情况：

| 场景 | 为什么有用 |
| --- | --- |
| 输出风格很难只靠文字描述 | 示例比规则更直观 |
| 模型总是漏掉某个字段 | 示例能强化结构 |
| 边界样例容易失败 | 示例能告诉模型遇到这种情况怎么处理 |

AI 学习助手可以加一个边界示例：

```text
用户：帮我学会所有 AI。

助手：
需要先澄清几个问题：
1. 你现在的编程和数学基础如何？
2. 你更想做应用开发、算法研究，还是产品落地？
3. 你每周能投入多少时间？
```

不要一开始塞很多示例。每个示例都要服务一个失败点。

## 成熟项目观察：OpenClaw 的启发

本章主案例是 [OpenClaw](https://github.com/openclaw/openclaw)。

对应源码 Lab：

- [Lab 03：个人助手与数字分身](../../labs/03-personal-assistants/README.md)

观察个人助手项目时，不要只看 Prompt 文案本身。更重要的是看它如何把用户输入变成可执行任务。

可以按这条链路观察：

```text
用户说一句话
-> 系统判断用户意图
-> 补充角色、目标、约束和上下文
-> 选择是否需要工具或技能
-> 生成结果或继续追问
```

本章只学习其中一小段：

```text
用户意图 -> 清楚的任务说明
```

迁移回 AI 学习助手，就是不要让模型自由聊天，而是把任务写清楚：

- 服务谁：AI Agent 初学者。
- 做什么：解释概念、指出误区、给练习。
- 不做什么：不假装读取资料，不直接处理过大的目标。
- 输出什么：三个固定部分。

等到第 9 章和第 10 章，我们再讨论工具、技能和 Agent。

## 项目锚点

AI 学习助手在本章要从“能回答”升级到“稳定教学回答”。

其他可选项目也可以用同样方法：

| 项目 | 本章 Prompt 任务 |
| --- | --- |
| 研究写作 Agent | 把研究主题拆成可搜索问题，并标注每个问题的目的 |
| 客服工单 Agent | 把工单分成类型、紧急程度、建议处理人，并说明理由 |
| 代码仓库助手 | 根据 README 和目录解释项目用途，给出阅读顺序 |

每个项目都要准备固定测试样例，而不是只靠一次成功回答判断质量。

## 检查题

先自己判断，再看参考答案。

| 问题 | 你的判断 |
| --- | --- |
| Prompt 越长一定越好吗？ |  |
| 为什么要用固定测试样例迭代 Prompt？ |  |
| Few-shot 示例应该什么时候加入？ |  |
| “你是专家，认真回答”为什么不够？ |  |

参考答案：

| 问题 | 参考判断 |
| --- | --- |
| 不一定。Prompt 应该解决具体失败点，过长反而难维护 |
| 固定样例能让你比较 v1 和 v2，而不是凭感觉判断 |
| 当规则描述不够直观、输出结构不稳定或边界样例反复失败时加入 |
| 它没有明确用户、任务、约束、输出要求和失败处理 |

## 本章小结

这一章你学会了把随意提问改成可测试的任务说明。

你现在应该已经有：

- 一组固定 Prompt 测试样例。
- 一个 v1 Prompt。
- 至少一次失败记录。
- 一个说明改动原因的 v2 Prompt。
