# 第 11 章：Agent 执行循环与 ReAct

> 状态：planned

## 本章定位

讲清楚 Agent 如何在目标、思考、行动、观察和反馈之间循环执行。

## 承接上一章

上一章定义了 Agent 的边界。本章开始解释 Agent 内部最小执行机制。

## 铺垫下一章

下一章会讲任务拆解和计划执行。本章需要先让读者理解单步行动和观察反馈。

## 学习目标

- 能理解 Agent 的目标、推理、行动、观察和停止条件。
- 能解释 ReAct 为什么把推理和行动结合起来。
- 能设计一个有最大步数和失败退出的简单 Agent loop。

## 本章产出

- 一个最小 Agent loop 示例。
- 一张 Agent 执行循环图。
- 一份执行轨迹记录样例。

## 学习任务

- 为项目实现一个最多 3 步的 Agent loop。
- 每一步都记录目标、行动、观察和停止判断。
- 准备一个失败案例，观察 Agent 是否会重复调用或错误停止。

## 项目锚点

“AI 学习助手”在本章可以根据用户目标选择工具，例如查询资料、生成练习、检查答案。研究写作 Agent 可以在搜索、阅读和摘要之间循环。

## 成熟项目讲解

- 主案例：LangGraph。
- 对比案例：OpenClaw、OpenHands、SmolAgents。
- 讲解切口：Agent loop 如何记录观察、选择行动、处理失败和停止循环。
- 对应源码 Lab：[Lab 01：通用核心框架](../../labs/01-core-frameworks/README.md)、[Lab 02：编程 Agent](../../labs/02-coding-agents/README.md)、[Lab 08：轻量入门与研究级 Agent](../../labs/08-lightweight-research/README.md)。
- 迁移到项目：让“AI 学习助手”完成一次查询资料、生成练习、检查答案的可追踪循环。

## 开源案例观察

观察 LangGraph 的可恢复执行和 OpenClaw 的工具执行轨迹。重点看 Agent loop 如何停止、如何记录观察结果、如何避免重复调用。

## 本章要写什么

- Agent 执行循环。
- ReAct 的基本思想。
- 行动结果如何影响下一步。
- 何时停止执行。
- 循环失控和重复调用的风险。

## 本章不要写什么

- 不要深入长期计划。
- 不要提前讲多 Agent。
- 不要让示例无限循环。

## 小白易卡点

- 没有设置最大步数，导致循环失控。
- 不知道 Observation 应该如何反馈给下一步。
- 把中间推理过程和最终用户可见输出混在一起。

## 建议示例

实现一个最多执行 3 步的简单 Agent，让它根据观察结果决定下一步。

## 建议图解

画一张 Agent loop：目标、推理、工具调用、观察、继续或停止。
