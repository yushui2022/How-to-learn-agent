# 第 14 章：Multi-Agent 多智能体协作

> 状态：planned

## 本章定位

讲清楚什么时候需要多个 Agent，以及如何设计角色分工和协作边界。

## 承接上一章

上一章讲了状态和记忆。本章会把单个 Agent 扩展为多个角色协作，需要明确共享信息和交接方式。

## 铺垫下一章

下一章会讲 Agent 评估。多 Agent 系统更难判断是否有效，因此本章结束后要自然进入评估问题。

## 本章要写什么

- 多 Agent 的适用场景。
- 角色分工和职责边界。
- Supervisor / Worker 模式。
- Reviewer、Planner、Executor 等角色。
- 多 Agent 的成本、延迟和失控风险。

## 本章不要写什么

- 不要为了显得高级而强行多 Agent。
- 不要忽略通信成本。
- 不要把多 Agent 写成固定框架教程。

## 建议示例

构建一个研究员、写作者、审阅者三角色的小流程。

## 建议图解

画一张多 Agent 协作图，标出输入、角色、消息和最终输出。
