# 第 14 章：Multi-Agent 多智能体协作

> 状态：planned

## 本章定位

讲清楚什么时候需要多个 Agent，以及如何设计角色分工和协作边界。

## 承接上一章

上一章讲了状态和记忆。本章会把单个 Agent 扩展为多个角色协作，需要明确共享信息和交接方式。

## 铺垫下一章

下一章会讲 Agent 评估。多 Agent 系统更难判断是否有效，因此本章结束后要自然进入评估问题。

## 学习目标

- 能判断什么时候需要多 Agent，什么时候单 Agent 更合适。
- 能设计角色分工和消息交接方式。
- 能识别多 Agent 的成本、延迟和失控风险。

## 本章产出

- 一张多 Agent 协作结构图。
- 一份角色职责表。
- 一个研究员、写作者、审阅者的小流程设计。

## 学习任务

- 为项目设计 2 到 3 个 Agent 角色，并写清楚每个角色的职责边界。
- 定义角色之间传递什么信息，以及什么时候停止协作。
- 对比单 Agent 方案和多 Agent 方案的成本、延迟和质量风险。

## 项目锚点

“AI 学习助手”可以拆成学习规划者、资料检索者、练习设计者和审阅者。研究写作 Agent 最适合作为本章主项目，使用研究员、写作者、审阅者三角色流程。

## 成熟项目讲解

- 主案例：CrewAI、MetaGPT。
- 对比案例：AutoGen、OpenClaw。
- 讲解切口：角色、任务、消息交接、审阅机制和退出条件。
- 对应源码 Lab：[Lab 04：多智能体协作](../../labs/04-multi-agent/README.md)。
- 迁移到项目：先用研究写作 Agent 做三角色流程，再判断“AI 学习助手”是否真的需要多 Agent。

## 开源案例观察

观察 AutoGen、CrewAI 和 OpenClaw 的多角色协作思路。重点不是“多开几个 Agent”，而是角色边界、通信协议、审阅机制和退出条件。

## 本章要写什么

- 多 Agent 的适用场景。
- 角色分工和职责边界。
- Supervisor / Worker 模式。
- Reviewer、Planner、Executor 等角色。
- 多 Agent 的成本、延迟和失控风险。

## 本章不要写什么

- 不要为了显得高级而强行多 Agent。
- 不要忽略通信成本。
- 不要把多 Agent 写成固定框架教程。

## 小白易卡点

- 觉得 Agent 越多能力越强。
- 没有定义角色边界，导致重复劳动。
- 没有退出条件，导致反复讨论。

## 建议示例

构建一个研究员、写作者、审阅者三角色的小流程。

## 建议图解

画一张多 Agent 协作图，标出输入、角色、消息和最终输出。
