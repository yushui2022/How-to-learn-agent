# 第 13 章：Memory 与 State

> 状态：planned

## 本章定位

讲清楚 Agent 如何管理对话上下文、长期记忆和任务状态，让任务可以持续、恢复和迭代。

## 承接上一章

上一章讲了计划和执行。多步骤执行需要保存当前进度、中间结果和关键决策，本章负责解释这些状态。

## 铺垫下一章

下一章会讲多 Agent。多个 Agent 协作时更需要明确共享状态、私有记忆和交接信息。

## 学习目标

- 能区分短期上下文、长期记忆和任务状态。
- 能判断什么信息应该进入上下文，什么信息应该持久化。
- 能设计一个简单的任务恢复和状态更新流程。

## 本章产出

- 一张 Memory / State 关系图。
- 一份任务状态字段设计。
- 一个记忆写入、读取和清理的最小示例。

## 学习任务

- 为项目设计任务状态字段，例如当前目标、已完成步骤、下一步、失败原因。
- 区分哪些信息是短期上下文，哪些信息可以作为长期记忆保存。
- 实现或描述一次任务中断后如何恢复。

## 项目锚点

“AI 学习助手”在本章要记住学习目标、掌握程度和未完成任务，但不能无限保存聊天记录。代码仓库助手可以记住当前分析目标、涉及文件和测试结果。

## 成熟项目讲解

- 主案例：mem0。
- 对比案例：Letta、LangGraph。
- 讲解切口：长期记忆、会话状态、记忆检索、记忆更新和删除机制。
- 对应源码 Lab：[Lab 05：记忆、推理与模型服务专项](../../labs/05-memory-reasoning/README.md)、[Lab 03：个人助手与数字分身](../../labs/03-personal-assistants/README.md)。
- 迁移到项目：让“AI 学习助手”只记住学习目标、进度和薄弱点，不默认保存所有聊天内容。

## 开源案例观察

mem0 是本章核心案例。重点观察它如何处理用户记忆、会话记忆、记忆检索和记忆更新，并和 LangGraph 的任务状态管理区分开。

## 本章要写什么

- 短期上下文和长期记忆的区别。
- 什么信息应该进入上下文。
- 什么信息应该存入外部存储。
- 任务状态如何设计。
- 上下文压缩和恢复任务。

## 本章不要写什么

- 不要把 Memory 等同于数据库教程。
- 不要提前讲复杂多 Agent 状态同步。
- 不要鼓励无限保存用户信息。

## 小白易卡点

- 把所有聊天记录都当成长期记忆。
- 不知道状态、日志和记忆之间的区别。
- 忽略用户隐私和记忆清理。

## 建议示例

让 Agent 记住用户偏好，并在后续任务中使用，同时展示如何查看和清理记忆。

## 建议图解

画一张短期上下文、长期记忆、任务状态之间的关系图。
