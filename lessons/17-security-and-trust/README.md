# 第 17 章：Security 与 Trust

> 状态：planned

## 本章定位

讲 AI Agent 项目中的安全、权限、可靠性和可信边界，避免读者把 demo 直接搬到生产环境。

## 承接上一章

上一章讲了观测和调试。本章基于可观测执行过程，继续讨论如何控制风险。

## 铺垫下一章

下一章会讲生产化。安全、权限和可靠性是上线前必须处理的问题。

## 学习目标

- 能识别 Prompt Injection、越权工具调用和敏感数据泄露风险。
- 能设计最小权限、人工审批和安全停止机制。
- 能说明安全控制和用户体验之间的取舍。

## 本章产出

- 一张安全边界图。
- 一份高风险工具权限清单。
- 一个带人工确认的工具调用示例。

## 学习任务

- 列出项目中所有工具和数据访问点，标注风险等级。
- 设计至少 3 条安全规则，例如高风险操作需要人工确认。
- 准备一个 Prompt Injection 或越权调用样例，并说明系统应该如何拒绝。

## 项目锚点

“AI 学习助手”在本章要限制记忆保存和资料访问范围。客服工单 Agent 要重点处理用户隐私、订单查询权限和人工确认。代码仓库助手要限制写文件、运行命令和提交修改的权限。

## 成熟项目讲解

- 主案例：OpenClaw。
- 对比案例：browser-use、OpenHands。
- 讲解切口：本地运行、权限边界、高风险工具、人工确认和安全沙箱。
- 对应源码 Lab：[Lab 06：浏览器与工具自动化](../../labs/06-browser-tools/README.md)、[Lab 02：编程 Agent](../../labs/02-coding-agents/README.md)。
- 迁移到项目：为“AI 学习助手”明确哪些信息可以记忆、哪些工具必须确认、哪些动作禁止自动执行。

## 开源案例观察

OpenClaw 是本章重点案例。观察它如何处理本地运行、权限边界、工具风险和安全沙箱，再迁移到自己的 Agent 项目。

## 本章要写什么

- Prompt Injection 和越权工具调用。
- 工具权限最小化。
- 人工确认和审批。
- 敏感数据处理。
- 失败兜底和安全停止。

## 本章不要写什么

- 不要制造恐慌。
- 不要只讲原则，不给工程约束方法。
- 不要鼓励 Agent 直接执行高风险操作。

## 小白易卡点

- 以为安全只靠一句系统提示词就够。
- 没有区分低风险工具和高风险工具。
- 忽略日志审计和人工确认。

## 建议示例

展示一个恶意输入如何诱导工具误用，再通过权限限制和人工确认降低风险。

## 建议图解

画一张安全边界图：用户输入、模型、工具、权限、审批、日志。
