# 00：课程准备与协作方式

> 状态：planned

## 本章定位

这里不是正式知识章节，而是帮助读者和贡献者准备好学习环境、阅读方式和协作方式。

## 承接上一章

无。它是全书入口。

## 铺垫下一章

下一章会开始解释 AI 项目到底在做什么。读者在进入下一章前，应该知道这本教程怎么读、代码怎么运行、遇到问题如何反馈。

## 学习目标

- 知道这门课程的学习路线和章节关系。
- 知道如何准备本地环境、运行示例、提交反馈。
- 知道如何作为贡献者认领章节、示例、图解或审稿任务。

## 本章产出

- 一份本地学习环境检查清单。
- 一份贡献者参与流程说明。
- 一张全书学习路线图。

## 学习任务

- 完成本地环境检查，记录 Git、编辑器和运行时是否可用。
- 阅读 [PROJECT_TRACKS.md](../../PROJECT_TRACKS.md)，选择一个主线项目或可选项目作为自己的练习方向。
- 在本地建立一个学习记录文件，后续每章记录任务产出和遇到的问题。

## 项目锚点

本章不实现业务功能，但要为所有项目准备工作区。读者需要明确自己后续会跟随“AI 学习助手”，还是选择研究写作 Agent、客服工单 Agent 或代码仓库助手作为主练项目。

## 成熟项目讲解

- 主案例：Microsoft AI Agents for Beginners、OpenClaw、mem0。
- 讲解切口：成熟项目如何组织 README、课程入口、环境准备、示例目录和贡献指南。
- 对应源码 Lab：[Lab 01：通用核心框架](../../labs/01-core-frameworks/README.md)、[Lab 05：记忆、推理与模型服务专项](../../labs/05-memory-reasoning/README.md)。
- 迁移到项目：为本课程统一仓库结构、章节状态、协作规则和案例引用方式。

## 开源案例观察

先浏览 OpenClaw、mem0 等项目的 README、目录和贡献入口。观察一个成熟开源项目如何组织文档、示例、安装方式和社区协作，不要求理解源码。

## 本章要写什么

- 教程适合谁阅读。
- 推荐学习路径。
- 本地环境、编辑器、命令行和 Git 基础。
- 示例代码的运行方式。
- 如何参与贡献、认领章节和提交 PR。

## 本章不要写什么

- 不要提前讲 LLM、RAG 或 Agent 的技术细节。
- 不要把环境准备写成某个云厂商的专属教程。

## 小白易卡点

- 不知道应该先读哪一章。
- 不知道示例代码应该在哪里运行。
- 不知道遇到错误时应该提交 Issue 还是自己继续尝试。

## 建议示例

一个最小的环境检查命令，例如确认 Python、Node 或 Git 是否可用。具体技术栈等示例代码规划确定后再补。

## 建议图解

画一张“学习路径地图”，展示从第 1 章到综合项目的整体路线。
