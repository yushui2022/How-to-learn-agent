# 00：课程准备与协作方式

> 状态：drafting

本章不是技术知识点，而是整门课的入口。读者在这里要完成三件事：知道怎么学、选定一个练习项目、建立自己的学习记录。

学完本章后，读者不需要理解 LLM、RAG 或 Agent 的技术细节，但应该知道后续每一章会如何推进项目，以及成熟项目讲解和源码 Lab 应该怎么用。

## 本章定位

这里帮助读者和贡献者准备好学习环境、阅读方式、项目主线和协作方式。

本章解决的问题是：

- 这门课应该按什么顺序学。
- 每章学习后应该留下什么产出。
- 读者应该跟随哪个项目做练习。
- 成熟项目讲解和源码 Lab 在课程中怎么使用。
- 贡献者如何认领章节、示例、图解或审稿任务。

## 承接上一章

无。它是全书入口。

## 铺垫下一章

下一章会开始解释 AI 项目到底在做什么。读者在进入下一章前，应该已经知道这本教程怎么读、代码怎么运行、遇到问题如何记录和反馈。

## 学习目标

- 知道这门课程的主线结构。
- 知道如何选择自己的练习项目。
- 知道如何使用每章的成熟项目讲解和源码 Lab。
- 完成本地环境和学习记录准备。
- 知道贡献者如何参与课程共建。

## 本章产出

- 一份本地学习环境检查结果。
- 一个已选定的练习项目方向。
- 一个学习记录文件。
- 一次成熟开源项目 README 观察记录。

## 你会用这门课做什么

这门课不是只讲 Agent 概念，也不是只堆框架名。它的目标是让读者从一个小 AI 项目开始，逐步做出一个可以解释、可以调试、可以评估、可以控制风险的 Agent 项目。

默认贯穿项目是：

```text
AI 学习助手
```

它会从一个最小 LLM 调用开始，逐步加入 Prompt、结构化输出、工作流、RAG、工具调用、Agent loop、记忆、评估、观测、安全和生产化。

如果读者更想做别的方向，也可以选择一个可选项目：

- 研究写作 Agent
- 客服工单 Agent
- 代码仓库助手

建议第一次系统学习时优先跟随“AI 学习助手”。它业务简单，适合把注意力放在 AI 工程和 Agent 能力本身。

## 这门课的三条线

后续章节会同时推进三条线。

| 学习线 | 你要做什么 | 放在哪里 |
| --- | --- | --- |
| 主线课程 | 按章节学习概念和方法 | `lessons/` |
| 项目主线 | 每章给自己的项目增加一个小资产 | `PROJECT_TRACKS.md`, `projects/` |
| 源码 Lab | 看成熟项目如何解决同类问题 | `labs/`, `LESSON_CASE_STUDIES.md` |

每一章都不是孤立文章。标准学习方式是：

```text
理解本章问题
-> 完成本章最小任务
-> 看一个成熟项目的相关切口
-> 把观察结果迁移回自己的项目
-> 留下一份项目资产
```

比如第 13 章讲 Memory 与 State，就不会只讲“记忆是什么”。它会让读者看 mem0 和 Letta 如何处理记忆，再回到“AI 学习助手”，设计自己的学习目标、学习进度和薄弱点记忆。

## 准备本地环境

本课程会逐步加入代码示例。当前阶段先准备最基础的工具：

- Git：用于克隆仓库、查看改动和提交贡献。
- 编辑器：用于阅读 Markdown、写代码和记录学习过程。
- 命令行：用于运行示例、查看错误和保存输出。
- Python 或 Node.js：后续示例会根据章节需要选择其中一种。

建议先记录这些命令的输出：

```powershell
git --version
python --version
node --version
npm --version
```

如果某个命令不可用，不需要在本章解决所有环境问题。先把错误记录下来，后续示例真正需要它时再处理。

## 选择你的练习项目

进入第 1 章之前，读者需要先选一个练习方向。

推荐选择：

```text
AI 学习助手
```

选择它的原因是：

- 场景容易理解。
- 不需要复杂业务系统。
- 每章都能自然加一个能力。
- 适合小白从 LLM 调用过渡到 Agent。

如果读者已经有明确兴趣，可以选可选项目。但要注意：可选项目不能改变主线学习顺序，只是把每章产出换成自己的业务场景。

## 如何看成熟项目

本课程会讲 OpenClaw、mem0、LangGraph、OpenHands、browser-use、Dify、SmolAgents 等成熟项目。

但初学者不要一开始就试图读完整源码。成熟项目讲解只读一个小切口：

- 第 0 章只看 README、目录结构、贡献入口。
- 第 3 章只看 LiteLLM 为什么需要模型网关。
- 第 9 章只看工具 Schema 和调用日志。
- 第 13 章只看记忆写入、检索、更新和删除。
- 第 17 章只看权限边界和人工确认。

读成熟项目的目标不是复刻它，而是回答：

- 它解决什么真实问题？
- 它为什么这样组织？
- 本章能学它哪一小块？
- 哪些复杂度现在不要照搬？
- 这一小块如何迁移回自己的项目？

## 成熟项目讲解

- 主案例：Microsoft AI Agents for Beginners、OpenClaw、mem0。
- 讲解切口：成熟项目如何组织 README、课程入口、环境准备、示例目录和贡献指南。
- 对应源码 Lab：[Lab 01：通用核心框架](../../labs/01-core-frameworks/README.md)、[Lab 05：记忆、推理与模型服务专项](../../labs/05-memory-reasoning/README.md)。
- 迁移到项目：为本课程统一仓库结构、章节状态、协作规则和案例引用方式。

## 开源案例观察

本章只观察成熟项目的外层组织，不要求理解源码。

建议观察：

- README 第一屏是否能说明项目解决什么问题。
- 是否有清晰的安装或开始方式。
- 是否有示例目录。
- 是否有贡献指南。
- 是否能看出项目面向新手、开发者还是企业用户。

观察结束后，把结果写进学习记录，不需要写长文。

## 学习任务

1. 完成本地环境检查，记录 Git、编辑器、Python、Node.js 是否可用。
2. 阅读 [PROJECT_TRACKS.md](../../PROJECT_TRACKS.md)，选择一个主线项目或可选项目作为练习方向。
3. 阅读 [LESSON_CASE_STUDIES.md](../../LESSON_CASE_STUDIES.md)，理解每章成熟项目讲解如何嵌入课程。
4. 建立自己的学习记录，可以参考 [learning-record-template.md](./learning-record-template.md)。
5. 任选一个成熟项目，观察它的 README 和目录结构，写下 3 条值得学习的组织方式。

## 项目锚点

本章不实现业务功能，但要为所有项目准备工作区。

读者需要明确自己后续会跟随“AI 学习助手”，还是选择研究写作 Agent、客服工单 Agent 或代码仓库助手作为主练项目。

对于“AI 学习助手”，本章只产出一件事：

```text
项目选择说明：我为什么选择 AI 学习助手，以及我希望它最终帮我解决什么学习问题。
```

## 本章不要写什么

- 不要提前讲 LLM、RAG 或 Agent 的技术细节。
- 不要把环境准备写成某个云厂商的专属教程。
- 不要要求读者现在读完整开源项目源码。
- 不要让读者一开始就设计复杂系统。

## 小白易卡点

- 不知道应该先读哪一章。
- 不知道每章学完要留下什么产出。
- 看到 OpenClaw、LangGraph、mem0 这类项目后，以为自己必须马上读懂全部源码。
- 环境检查时遇到报错，不知道应该先记录还是立即解决。

本章的处理方式是：先记录，不要卡死。只有后续章节真正需要某个工具时，再解决对应环境问题。

## 建议示例

本章适合配一个“环境检查记录”示例，展示如何把命令输出和问题记录到学习记录里。

示例不需要自动化脚本，先用手动记录即可。后续如果课程代码示例统一选择 Python 或 Node.js，再补一个真正的环境检查脚本。

## 建议图解

本章适合画一张“课程学习路线图”：

```text
主线课程
  -> 项目主线
  -> 成熟项目讲解
```

## 完成标准

完成本章后，读者应该能回答：

- 我选择哪个项目作为练习方向？
- 我本地有哪些工具可用，哪些暂时不可用？
- 我后续每章会把学习结果记录在哪里？
- 我知道成熟项目讲解不是项目广告，而是每章的工程参照。
- 我知道源码 Lab 不是附录，而是配合 lesson 使用。

如果这些问题都能回答，就可以进入第 1 章。
